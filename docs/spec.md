# Специфікація Предметної Моделі (Спринт 1)

Цей розділ описує всі класи, їхні поля, методи та ієрархію винятків першого спринту, щоб інші модулі знали, як правильно взаємодіяти з даними.

## 1. Базові сутності (Класи)

**Зупинка (Stop)**
- `stop_id` (str) — унікальний ідентифікатор.
- `name` (str) — назва зупинки.
- `lat` (float) — широта.
- `lon` (float) — довгота.

**Маршрут (Route)**
- `route_id` (str) — унікальний ідентифікатор.
- `transport` (об'єкт класу TransportUnit) — тип транспорту, що обслуговує маршрут.
- `stops` (list[str]) — список зберігає лише ID зупинок (рядки), а не самі об'єкти зупинок.

**Рейс (Trip)**
- `trip_id` (str) — унікальний номер рейсу.
- `route` (об'єкт класу Route) — маршрут, за яким виконується рейс.
- `start_time` (int) — час відправлення.
*Контракт часу:* Парсер (Роль B) має самостійно конвертувати час із формату GTFS у ціле число (хвилини від опівночі) і передавати сюди вже готовий `int`.

**Пасажир (Passenger)**
- `passenger_id` (str) — ідентифікатор пасажира.
- `name` (str) — ім'я (за замовчуванням "Unknown").

## 2. Ієрархія Транспорту

**Базовий абстрактний клас: TransportUnit**
- `speed` (float) — швидкість (км/год).
- `capacity` (int) — місткість.
- `fare` (float) — вартість проїзду.

**Нащадки:** `Bus`, `Tram`, `Trolleybus`, `Metro`.
*Контракт створення:* Парсер не вираховує і не передає ці параметри при створенні об'єктів. Швидкість, місткість та вартість проїзду різні для кожного виду і жорстко зашиті всередині конструкторів кожного класу-нащадка.

## 3. Мережа (Network)

Клас `Network` виступає як композиція зупинок і ребер графа.

**Поля:**
- `stops` (dict) — словник для зберігання об'єктів зупинок (ключ: `stop_id`).
- `routes` (dict) — словник для зберігання об'єктів маршрутів (ключ: `route_id`).
- `edges` (dict) — словник для збереження зв'язків між зупинками (суміжність).

**Методи:**
- `add_node(stop)` — додавання вузла (зупинки) до мережі.
- `remove_node(stop_id)` — вилучення вузла з обов'язковою перевіркою зв'язності мережі (якщо при видаленні граф розпадається на незв'язні частини — має підійматися виняток).

## 4. Ієрархія Винятків

Всі власні помилки предметної області наслідуються від базового класу **NetworkError**. Інші модулі (наприклад, парсер чи алгоритми) повинні перехоплювати їх у разі проблем:
- `NetworkError` — базовий клас помилки мережі.
- `StopNotFoundError` — підіймається, якщо запитаної зупинки немає в мережі.
- `RouteNotFoundError` — підіймається, якщо не знайдено маршрут.
- `DisconnectedNetworkError` — підіймається, якщо порушується зв'язність графа (наприклад, при видаленні критичного вузла).
- `ScheduleError` — помилки, пов'язані з некоректним розкладом чи відсутністю рейсів.
